## 2. 제품 개요

Sequence Coach는 사용자가 설명한 설비 동작 조건을 분석해 PLC 제어 프로그램 설계를 돕는 멀티 에이전트 프로그램이다. 팀장 에이전트가 다섯 전문가 에이전트의 작업을 조정하고, 요구사항 정리부터 설계·안전 검토·시뮬레이션·수정 및 산출물 작성까지 단계별 결과를 취합한다.

제품은 설계 지원 도구다. 생성된 회로와 프로그램이 실제 설비에 안전하거나 법규에 적합하다고 자동으로 인증하지 않는다. 실제 설비 적용 전에는 자격을 갖춘 사람이 설계·위험성 평가·현장 조건을 확인하고 승인해야 한다.

## 3. 해결하려는 문제

- 자연어로 작성된 동작 요청에는 입력 조건, 예외 상황, 정지 조건 등이 빠지거나 모호할 수 있다.
- 요구사항, 회로 설계, 안전 검토, 동작 검증이 분리되면 단계 사이의 조건 누락과 해석 차이를 발견하기 어렵다.
- 설계 오류와 수정 근거가 명확히 연결되지 않으면 결과를 검토하고 유지보수하기 어렵다.
- PLC 기종·명령어·개발 환경에 따라 프로그램 형식과 호환 가능한 산출물이 다르다.

## 4. 목표와 비목표

### 목표

1. 요청자의 설명을 확인 가능한 동작 요구사항과 순서도로 구조화한다.
2. 요구사항과 추적 관계가 있는 PLC 제어 회로·프로그램 설계를 생성한다.
3. 안전 관련 우려와 추가 확인이 필요한 조건을 설계 검토 과정에서 드러낸다.
4. 지정된 시뮬레이터에서 가능한 범위의 동작 검증을 수행하고 결과를 요구사항에 연결한다.
5. 검증 결과에 따른 수정 사항, 최종 설계 및 보고서를 제공한다.
6. 대상 MELSEC PLC 기종과 개발 환경이 확인된 경우에만 지원이 검증된 파일 형식으로 산출한다.

### 비목표

- 사람의 검토 없이 설비에 프로그램을 전송하거나 설비를 원격으로 구동하는 것
- 산업안전보건법 또는 다른 법령에 대한 법률 자문, 공식 적합성 인증이나 안전 보증
- 명시적으로 지원·검증하지 않은 PLC 기종, 펌웨어, MELSOFT 버전 또는 파일 형식의 호환성 보장
- 안전 계전기, 비상정지 회로 등 물리적 안전 장치의 필요성을 소프트웨어만으로 대체하는 것

## 5. 사용자와 주요 사용 사례

### 주요 사용자

- 동작 순서를 자연어로 설명하고 PLC 설계 초안을 요청하는 설비 담당자
- 생성 결과를 검토하고 실제 장비 적용 여부를 결정하는 PLC 엔지니어·안전 담당자

### 주요 사용 사례

1. 사용자가 설비 목적, 입력·출력, 동작 순서, 정지·복귀 조건, PLC 기종과 개발 환경을 입력한다.
2. 팀장 에이전트는 부족하거나 충돌하는 요구사항을 찾아 사용자에게 확인한다.
3. 요구사항 분석 에이전트가 확인된 요구를 순서도와 설계 입력 자료로 정리한다.
4. 회로 설계 에이전트가 해당 요구에 맞는 제어 설계를 작성한다.
5. 안전 검토 에이전트가 알려진 위험과 확인 필요 사항을 검토한다.
6. 안전 검토를 통과한 설계만 회로 검증 에이전트가 시뮬레이션 대상으로 전달한다.
7. 회로 검증 에이전트가 요구사항별 실행 결과와 오류 위치를 보고한다.
8. 수정 및 보고서 에이전트가 발견된 오류를 반영하고 최종 설계·산출물·제한사항을 정리한다.
9. 사용자가 결과를 내려받아 적격한 담당자와 함께 검토한 뒤 별도 절차로 실제 장비 적용을 결정한다.

## 6. 에이전트 구성과 책임

| 에이전트 | 책임 | 주요 결과 |
| --- | --- | --- |
| 팀장 에이전트 | 전체 작업 흐름과 상태 관리, 전문가 호출, 결과 통합, 누락·충돌 확인, 사용자 확인 요청 | 진행 상태, 통합 결과, 차단 사유 |
| 요구사항 분석 에이전트 | 요청을 동작 조건으로 정리하고 모호성·누락을 표시하며 순서도와 설계 입력을 작성 | 요구사항 목록, 순서도, 입출력 후보, 미결정 질문 |
| 회로 설계 에이전트 | 승인된 설계 입력에 따라 제어 회로·PLC 프로그램 초안을 작성 | 회로·프로그램 초안, 주소·기기 목록, 설계 근거 |
| 안전 검토 에이전트 | 제공된 법규·표준 자료와 위험 검토 기준에 따라 위험 요소 및 추가 검토 사항을 식별 | 검토 결과, 근거 출처, 위험·미확인 항목, 통과 또는 차단 |
| 회로 검증 에이전트 | 승인된 설계와 시험 시나리오를 시뮬레이터에서 검증하고 요구사항별 결과를 기록 | 시험 결과, 실패 재현 조건, 오류 위치와 분석 |
| 수정 및 보고서 에이전트 | 검증 결과를 반영해 설계를 수정하고 수정 추적표·최종 보고서·지원되는 산출물을 작성 | 수정 설계, 변경 내역, 최종 보고서, 산출물 또는 미지원 사유 |

각 에이전트는 맡은 단계의 결과와 근거를 구조화해 반환한다. 팀장 에이전트는 결과가 없거나 불완전한 상태를 성공으로 표시하지 않는다.

## 7. 기능 요구사항

### 입력과 요구사항 정리

- **FR-01** 사용자는 동작 설명, 설비 및 공정 정보, 입력·출력 정보, 정상·예외·정지·복귀 조건을 입력할 수 있어야 한다.
- **FR-02** 사용자는 대상 PLC의 제품군·CPU·펌웨어, 프로그래밍 언어 또는 표기법, MELSOFT 제품·버전을 제공할 수 있어야 한다. 필수 정보가 없으면 시스템은 호환 파일을 만들었다고 주장하지 않고 확인을 요청해야 한다.
- **FR-03** 시스템은 모호하거나 상충하는 안전·동작 조건을 임의로 채우지 않고 질문하거나 미결정으로 표시해야 한다.
- **FR-04** 요구사항 분석 결과에는 고유 식별자, 선행 조건, 입력, 기대 출력·상태, 예외 및 완료 조건이 포함되어야 한다.
- **FR-05** 순서도와 입출력 목록은 회로 설계 및 후속 시험에서 같은 식별자로 추적할 수 있어야 한다.

### 설계와 안전 검토

- **FR-06** 회로 설계는 요구사항 식별자와 연결된 동작 설명, 입출력·기기 할당, 제어 논리 및 미해결 가정을 포함해야 한다.
- **FR-07** 안전 검토는 적용한 기준의 명칭·버전·출처와 검토 범위를 밝혀야 한다. 출처를 확인할 수 없는 법령·표준 내용은 확정된 근거로 제시하지 않아야 한다.
- **FR-08** 안전 검토 결과가 차단 또는 검토 불가이면 시뮬레이션 및 최종 산출 단계로 진행하지 않아야 한다. 사용자가 검토를 요청할 수 있도록 차단 사유와 필요한 조치를 제공해야 한다.
- **FR-09** 안전 검토 에이전트는 법적 적합성 인증 또는 실제 설비의 안전 보증을 선언하지 않아야 한다.

### 검증, 수정 및 산출

- **FR-10** 회로 검증은 요구사항별 정상·경계·예외 시나리오와 기대 결과를 기록하고, 성공·실패·실행 불가를 구분해야 한다.
- **FR-11** 시뮬레이터나 대상 기종이 지원되지 않으면 실행 결과를 꾸며내지 않고 제한 및 대체 확인 방법을 보고해야 한다.
- **FR-12** 수정 및 보고서는 검증 실패와 수정 내용을 연결하고, 변경 전후 및 재검증 결과를 보존해야 한다.
- **FR-13** 최종 산출물에는 설계 버전, 대상 기종·도구 버전, 파일 형식, 생성 시각, 검증 상태와 알려진 제한이 포함되어야 한다.
- **FR-14** 지원되는 대상에서만 MELSEC 개발 환경과 호환성이 확인된 파일을 제공해야 한다. 호환성이 확인되지 않은 경우 중립적인 설계 자료를 제공하고 호환 파일 생성은 미지원으로 표시해야 한다.
- **FR-15** 사용자는 단계별 결과와 근거를 확인하고 산출물을 받을 수 있어야 한다. 자동 장비 전송은 제품 범위에서 제외한다.

## 8. 안전·품질 요구사항

- 모든 산출물은 초안임을 표시하며, 실제 설비 적용 전 사람의 검토가 필요하다는 안내를 포함한다.
- 위험이 미해결이거나 필수 조건이 누락된 경우 해당 설계를 다음 단계로 자동 승격하지 않는다.
- 설계·검토·시험·수정의 입력과 출력을 버전 및 추적 ID로 연결한다.
- 법규와 표준은 관할 지역, 적용 대상, 최신성 및 출처를 확인해야 한다. 적용 가능성을 자동으로 단정하지 않는다.
- 시뮬레이션은 현실 설비의 모든 고장·환경·배선 조건을 재현하지 못할 수 있음을 결과에 명시한다.
- 생성 파일은 파싱·형식 검사와 대상 개발 도구에서의 열기·컴파일 확인을 가능한 범위에서 수행하고, 수행하지 못한 검증은 분명히 밝힌다.
- 요청자 입력, 프로젝트 산출물, 법규 자료와 에이전트 결과는 권한을 가진 사용자만 접근할 수 있어야 한다. 보존 기간과 삭제 정책은 제품 운영 전에 정한다.

## 9. 완료 기준

- 6개 에이전트 각각의 책임과 단계별 입력·출력이 구현 가능하게 정의되어 있다.
- 요구사항에서 설계, 안전 검토, 시험, 수정, 최종 산출물까지 추적 관계가 유지된다.
- 누락·모호한 입력은 확인 요청으로 이어지며, 안전 검토 차단 또는 도구 미지원 상태에서 다음 단계로 넘어가지 않는다.
- 시뮬레이션하지 않은 결과와 검증하지 않은 파일 호환성을 성공으로 표시하지 않는다.
- 지원 대상 MELSEC 환경별로 내보내기·가져오기 및 컴파일 확인 절차를 정의하고 검증한다.
- 사용자와 적격 담당자가 최종 결과의 제한사항과 실제 적용 전 확인 책임을 이해할 수 있다.

## 10. 위험과 미결정 사항

| 항목 | 미결정 내용 또는 위험 | 제품 결정이 필요한 사항 |
| --- | --- | --- |
| PLC 지원 범위 | MELSEC PLC 제품군·CPU·펌웨어에 따라 명령과 파일 형식이 다를 수 있음 | 초기 지원 기종과 우선순위 |
| 프로그래밍 언어 | Ladder Diagram, Structured Text 등 지원 방식이 정해지지 않음 | 초기 언어 및 결과 표현 방식 |
| 개발 도구 | MELSOFT 제품 및 버전별 호환 절차가 다를 수 있음 | 지원 도구·버전과 실제 검증 환경 |
| 시뮬레이터 | 대상 PLC·명령어를 재현하는 도구와 연동 방식이 미정 | 시뮬레이터, 라이선스, 자동화 가능한 범위 |
| 법규·표준 | 관할 지역, 설비 종류, 적용 기준과 최신 자료가 미정 | 검토 대상 법규·표준, 자료 관리 책임자, 사람 검토 절차 |
| 안전 승인 | 자동 검토 결과만으로 실제 설비 안전을 보장할 수 없음 | 차단 해제 권한과 필수 사람 승인자 |
| 데이터 관리 | 도면·설비 정보 등 민감한 입력의 보존 범위가 미정 | 저장 위치, 접근 권한, 보존·삭제 정책 |
| 품질 목표 | 지원 범위별 정확도·검증 커버리지 목표가 미정 | 측정 지표와 출시 기준 |

## 11. 출시 전 필수 결정

초기 구현 전에 위 표의 지원 범위, 프로그래밍 언어, MELSOFT 버전, 시뮬레이터, 적용 법규·표준 및 사람 승인 절차를 제품 책임자와 현장 PLC·안전 담당자가 확정해야 한다. 이 결정이 완료되기 전에는 해당 영역을 지원 또는 인증한다고 홍보하지 않는다.
