## 2. 제품 개요

사용자가 웹에서 PLC 정보(MELSEC Q시리즈 중심)와 동작 조건을 입력하면, AI 에이전트가 **조건 분석 → 회로 설계 → 자동 검증 ⇄ 수정**을 거쳐 회로(래더/IL)와 검증 결과, 웹 모의 실행을 제공한다. 사용자는 홈페이지 하나에서 입력·진행 확인·결과 확인을 한다.

**가장 중요한 목표는 "가능한 한 정확한 회로 설계"** 이다. 그래서 AI의 판단과 정확해야 하는 계산(검증 규칙, 회로 동작 판정, 명령어 변환)을 분리한다. 후자는 일반 코드와 테스트로 처리한다.

제품은 설계 지원 도구다. 생성된 회로가 실제 설비에 안전하다고 인증하지 않으며, 실제 적용 전 자격을 갖춘 사람의 확인이 필요하다. 이 고지는 화면에 항상 표시한다.

## 3. 해결하려는 문제

- 자연어 조건에는 입력·예외·정지 조건이 빠지거나 모호한 부분이 있다.
- 설계와 검증이 분리되면 조건 누락과 해석 차이를 찾기 어렵다.
- 오류와 수정 근거가 연결되지 않으면 결과를 믿고 유지보수하기 어렵다.
- PLC 기종·명령어·개발 환경마다 쓸 수 있는 회로 형식이 다르다.

## 4. 범위

### 현재 지원 범위 (MVP)

- **MELSEC Q시리즈, 래더(IL 명령어 표기), GX Works2 / GX Developer** 만 지원한다. iQ-R·GX Works3·ST 등은 실행 전에 막고 이유를 알려 준다.
- 회로 요소: 접점(NO/NC), 직렬(AND), 병렬(OR), 출력 `OUT/SET/RST`, 타이머 `TON`, 카운터 `CTU`.
- 타이머 시간은 100ms 단위, 최대 K32767.

### 비목표

- 사람의 검토 없이 설비에 프로그램을 전송하거나 원격 구동하는 것
- 법률 자문, 공식 적합성 인증, 안전 보증
- 지원하지 않는 PLC 기종·펌웨어·MELSOFT 버전·파일 형식의 호환 보장
- 물리적 안전 장치(안전 계전기, 비상정지 회로)를 소프트웨어로 대체하는 것
- 설비로의 자동 다운로드

## 5. 사용자와 사용 흐름

주요 사용자는 동작 조건을 설명하는 설비 담당자와, 결과를 검토하는 PLC 엔지니어다.

1. **기본 설정**: PLC 시리즈·CPU·소프트웨어·타이머 단위 등 필수 정보를 선택하거나 입력한다. 값이 서로 맞지 않으면 화면과 서버가 같은 규칙으로 막는다.
2. **동작 조건**: 입출력(I/O) 목록과 동작 조건을 입력한다(CSV 가져오기, 템플릿 저장 지원).
3. **설계 요청**: 실행 버튼을 누르면 시작 전 사전 점검을 하고, 통과하면 에이전트가 일한다. 단계별 경과 시간과 총 경과 시간을 볼 수 있다.
4. **검증 결과**: 조건별 통과·실패, 검증 기준(팝업), "검증 신뢰도 낮음" 표시와 이유를 본다. 실패하면 수정 에이전트가 고친 뒤 다시 검증한다.
5. **모의 실행**: 웹 시뮬레이터에서 입력을 눌러 보며 회로 동작을 확인한다.
6. (예정) 명령어(IL) 파일 내려받기와 GX Simulator 확인 안내.

## 6. 에이전트와 코드의 역할

| 구성 | 종류 | 책임 | 상태 |
| --- | --- | --- | --- |
| 팀장 에이전트 | Copilot Studio | 작업 흐름 안내, 분석·설계 에이전트 호출, 진행 상태 응답 | 구현됨 |
| 분석 에이전트 | Copilot Studio | 입력을 조건·검증 방법(시험 틀)으로 정리. 질문은 최대 3개까지만 하고 모호하면 사용자에게 확인 | 구현됨 |
| 설계 에이전트 | Copilot Studio | 분석 결과로 회로(IR)를 작성해 제출. 규칙에 어긋나면 서버가 거부하고 다시 작성 | 구현됨 |
| 자동 검증 | **일반 코드** | 정적 검사, 스캔 시뮬레이터, 조건별 시험, 자동 안전 탐색 | 구현됨 |
| 수정 에이전트 | Copilot Studio | 검증 실패 원인을 받아 회로를 고침. 서버가 다시 검증 | 구현됨 |
| 결과·모의 실행 | 웹 화면 | 결과 요약, 조건별 결과, 설계 보기, 웹 시뮬레이터 | 구현됨 |
| 파일 생성 | 코드 | IL 파일, GX Simulator 확인 안내 | 예정 (#44) |

**v1에서 달라진 점**: 안전 검토 에이전트와 회로 검증 에이전트는 별도 AI로 두지 않고 **코드 검증**으로 대체했다(결과가 재현되고 테스트할 수 있어야 하기 때문). 수정 및 보고서 에이전트는 수정 에이전트와 결과 화면으로 나뉘었다.

## 8. 안전·품질 요구사항

- 모든 결과는 초안이며 "완성된 회로는 결코 안전을 보장하지 않으며 전문가 확인이 필요하다"는 안내를 유지한다.
- 에이전트의 응답이 비었거나 시간 초과(기본 180초)이면 성공으로 표시하지 않고 실패로 알린다.
- **설계 정확도를 위해 분석 단계를 건너뛰는 단축은 하지 않는다.** 단축은 입력 사전 점검과 대기 화면 개선으로만 한다.
- 시뮬레이터는 고정 10ms 스캔의 단순 모델이다. PLC 설정(CPU 성능 등)은 반영하지 못하며 실제 설비의 고장·배선을 재현하지 못한다. 결과 화면에 한계를 밝힌다.
- 검증하지 않은 것(GX Works 파일 호환, 실기 동작)은 성공으로 표시하지 않는다.
- 비밀값(API 키, Direct Line 암호)은 코드·이슈·채팅에 넣지 않는다.

## 9. 완료 기준

- 지원 범위(Q시리즈 래더)의 대표 회로(자기유지, 비상정지 인터록, 지연 ON/OFF 타이머)가 입력부터 결과·모의 실행까지 동작한다.
- 지원하지 않는 입력과 검증 불가 조건은 성공으로 위장하지 않고 이유와 함께 표시된다.
- 자동 테스트(백엔드 340개 통과)와 화면 빌드·린트가 CI에서 통과한다.
- IL 파일이 GX Works2 / GX Simulator에서 열리는지 실제 PC에서 확인하고 결과를 기록한다(#44).
- 배포 전에 노출된 비밀값을 모두 교체한다(#45).

## 10. 위험과 미결정 사항

| 항목 | 내용 | 대응 |
| --- | --- | --- |
| 에이전트 응답 시간 | 분석 약 50초, 설계 약 30초(Copilot Studio 생각 시간). 코드 쪽 지연은 아님 | 사전 점검·대기 화면으로 체감 개선. 지침 축약·모델 변경은 Studio에서 품질 확인 후 판단 |
| GX Works 파일 | 형식이 비공개 | #44에서 PoC 확인 후 구현. 확인 전에는 IL 텍스트만 제공 |
| 오프딜레이 | TOF 출력이 없어 TON+자기유지로 구성하고 `custom` 시험(신뢰도 낮음)으로 검증 | `off_delay` 시험 틀 추가 검토 |
| 시뮬레이터 | PLC 설정을 반영하지 않음 | 후속 개선 |
| 데이터 저장 | 개발용 SQLite. Render 무료 플랜은 재시작 시 사라질 수 있음 | 배포 시 별도 DB 필요 |
| 비밀값 | 개발 중 노출된 키가 있음 | 배포 전 교체 필수 |
| 법규·표준 | 안전 검토를 법규 기준으로 자동화하지 않음 | 제품 범위 밖. 사람 검토로 둔다 |
