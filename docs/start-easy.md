# 처음 시작하는 팀원을 위한 쉬운 가이드

처음이어도 괜찮아요. 아래 순서대로 한 단계씩 따라 하면 돼요. 더 자세한 약속은 [team-guide.md](team-guide.md)에 있어요.

**한눈에 보기:** 이슈 읽기 → 코드 받기 → 서버 켜기 → 브랜치 만들기 → 만들기 → PR 올리기 → 리뷰 후 합치기

---

## 0단계. 준비물 설치 (처음 한 번)

**이게 뭐예요?** 프로젝트를 돌리려면 컴퓨터에 프로그램 3개가 필요해요.

| 프로그램 | 용도 | 설치 |
|---|---|---|
| Git | 코드를 받고 올리는 도구 | git-scm.com |
| Python 3.12 | 백엔드(서버)를 돌리는 언어 | python.org |
| Node.js | 홈페이지를 돌리는 도구 | nodejs.org |

**확인하는 법:** PowerShell을 열고 `git --version`을 입력해요. 버전 숫자가 나오면 설치된 거예요.

---

## 1단계. 내 이슈 확인

**이게 뭐예요?** 이슈는 "내가 해야 할 일 카드"예요. 뭘 만들어야 하는지 여기에 적혀 있어요.

**실행법**
1. GitHub 저장소의 **Issues** 탭을 열어요.
2. 내 이름이 배정된 이슈를 클릭해요.
   - #41 회로 설계, #42 회로 검증, #43 회로 수정, #44 GX Works 파일·영상, #45 통합·배포
3. 안의 **체크리스트**를 읽어요. 이 항목들이 "다 만들었다"의 기준이에요.

**막히면** Copilot에게 "이슈 #41을 쉽게 설명해줘"라고 물어보세요.

---

## 2단계. 코드 받기

**이게 뭐예요?** GitHub에 있는 프로젝트 파일 전체를 내 컴퓨터에 복사해 오는 거예요. 처음 한 번만 해요.

**실행법**
1. 시작 메뉴에서 `PowerShell`을 열어요.
2. 프로젝트를 둘 위치로 이동해요. 예: `cd Desktop`
3. 아래를 한 줄씩 붙여 넣고 Enter를 눌러요.
```
git clone https://github.com/kimmin20001214-sudo/Sequence-coach
cd Sequence-coach
```

**결과:** `Sequence-coach` 폴더가 생겨요.

**안 되면**
- `git`이 없다고 나오면 0단계의 Git을 설치하고 PowerShell을 다시 열어요.
- GitHub 로그인 창이 뜨면 로그인해요. 저장소에 초대되지 않은 계정은 받을 수 없어요.

---

## 3단계. 서버 켜서 화면 보기

**이게 뭐예요?** 홈페이지(화면)와 백엔드(뒤에서 일하는 서버)를 내 컴퓨터에서 켜는 거예요. 가짜 분석 결과로 돌아가는 **데모 모드**라서 키가 필요 없어요.

**실행법**
1. 탐색기에서 `Sequence-coach` 폴더를 열어요.
2. **`start-demo.bat`** 을 더블클릭해요.
3. 검은 창 2개가 뜨고, 처음에는 설치 때문에 몇 분 걸려요.
4. 브라우저에 홈페이지(`http://localhost:5173`)가 열리면 성공이에요.

**끄는 법:** 검은 창 2개를 닫아요.

---

## 4단계. 내 브랜치 만들기

**이게 뭐예요?** 브랜치는 "내 작업용 복사본 줄기"예요. 원본(main)은 건드리지 않고, 내 줄기에서만 작업해요.

**실행법** (`Sequence-coach` 폴더의 PowerShell에서)
```
git switch -c feat/41-design
```
- 이름의 `41`은 내 이슈 번호로 바꿔요. 예: 검증 담당이면 `feat/42-verify`.

---

## 5단계. 만들기

**이게 뭐예요?** 이슈 체크리스트를 하나씩 만들어요. Copilot과 함께 하면 돼요.

**실행법**
1. 폴더를 VS Code나 Copilot 앱에서 열어요.
2. Copilot에게 말해요: "이슈 #41 체크리스트 첫 번째부터 만들어줘. 쉽게 설명해줘."
3. 먼저 **파이썬 함수와 테스트**를 만들어요. 에이전트는 나중에 붙여도 돼요.
4. 테스트를 돌려 확인해요.
```
backend\.venv\Scripts\python.exe -m pytest backend -q
```
`passed`가 나오면 통과예요.

**지켜야 할 것**
- `backend/app/contracts.py`는 팀 공용이에요. 바꾸기 전에 팀에 말해요.
- 비밀번호나 키는 코드에 쓰지 않아요.

---

## 6단계. 올리기 (PR 만들기)

**이게 뭐예요?**
- 커밋: 작업을 저장하는 것
- 푸시: 저장한 것을 GitHub에 올리는 것
- PR: "내 작업을 main에 합쳐 달라"는 요청서

**실행법**
```
git add -A
git commit -m "feat(#41): 회로 설계 함수 추가"
git push -u origin feat/41-design
```
1. 푸시하면 나오는 링크를 열거나, GitHub에서 **Compare & pull request**를 눌러요.
2. 양식을 채우고 **Create pull request**를 눌러요.

---

## 7단계. 리뷰와 합치기

**이게 뭐예요?** 다른 팀원이 내 작업을 검사하고, 괜찮으면 main에 합쳐요.

**실행법**
1. 팀 채팅에 "PR 올렸어요, 리뷰 부탁해요"라고 말해요.
2. 리뷰어가 의견을 남기면 고쳐서 같은 브랜치에 다시 푸시해요.
3. **다른 사람**이 승인하면 **Merge pull request**를 눌러 합쳐요.

**끝나면** 다음 작업은 `git switch main` → `git pull` 후 4단계부터 반복해요.

---

## 꼭 지킬 3가지

1. main에 직접 올리지 않아요. 항상 PR로 올려요.
2. 내 PR을 내가 승인하지 않아요.
3. 비밀번호와 키는 어디에도 올리지 않아요.
