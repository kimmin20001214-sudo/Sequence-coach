# 팀원 작업 가이드

각자 **자기 이슈 하나**를 맡아 만들고, 합치는 건 마지막에 한 번만 해요. 에이전트(Copilot Studio) 없이도 개발할 수 있어요.

## 1. 처음 한 번: 내 컴퓨터에 준비하기

1. 저장소를 받아요: `git clone https://github.com/kimmin20001214-sudo/Sequence-coach`
2. 폴더에서 **`start-demo.bat`** 을 더블클릭해요. 처음에는 설치 때문에 몇 분 걸려요.
   - 필요: Python 3.12, Node.js
   - 브라우저에 홈페이지(`http://localhost:5173`)가 열리면 성공이에요.
3. 데모 모드라 키나 Copilot Studio 연결이 필요 없어요. 분석 결과는 가짜(시연용)예요.
4. 테스트는 이렇게 돌려요.
   ```powershell
   backend\.venv\Scripts\python.exe -m pytest backend -q
   ```

## 2. 작업 순서 (매번 똑같아요)

1. 내 이슈를 읽고 **완료 기준** 체크리스트를 확인해요.
2. 최신 main에서 브랜치를 만들어요. 예: `git switch -c feat/41-design`
3. 작게 만들고, **테스트를 같이** 써요.
4. 커밋하고 푸시한 뒤 PR을 열어요. PR 양식의 칸을 채워요.
5. **다른 팀원**이 리뷰하고 나서 머지해요. 내 PR을 내가 머지하지 않아요.
6. 막히면 Copilot에게 "이슈 #번호를 쉽게 설명하고 어디부터 만들지 알려줘"라고 물어보세요.

## 3. 먼저 알아 둘 약속

- **계약 파일 `backend/app/contracts.py`는 팀 공용이에요.** 분석 결과(`StructuredRequirements`), 회로 데이터(`Ir`), 검증 결과(`VerificationResult`)가 여기에 있어요. 바꾸려면 팀에 먼저 알려요.
- 작업 상태 변경은 `backend/app/agents/orchestrator.py`의 함수로만 해요. 상태를 직접 고치지 않아요.
- 비밀번호, API 키, Direct Line 암호는 코드·이슈·채팅에 올리지 않아요.
- 완성된 회로는 안전을 보장하지 않아요. 안전 고지 문구를 빼지 않아요.

## 4. 이슈별 시작 카드

흐름은 `분석 → 설계(#41) → 검증(#42) → 수정(#43) → 파일·영상(#44) → 통합(#45)`이에요. 상태 이름은 `contracts.JOB_TRANSITIONS`에 있어요.

| 이슈 | 입력 | 출력 | 시작 방법 |
|---|---|---|---|
| #41 설계·IR | `StructuredRequirements` | `Ir` + 신호표 + 설명 | 새 폴더 `backend/app/plc/`에 IR→명령어(IL) 변환과 규칙 검사를 **일반 파이썬 함수로 먼저** 만들고 테스트해요. 그다음 설계 에이전트를 붙여요. |
| #42 검증 | `Ir`, 조건 목록 | `VerificationResult` | 정적 검사(이중 코일 등)와 스캔 시뮬레이터를 파이썬 함수로 만들어요. 자기유지·타이머 정상/고장 회로 테스트를 먼저 써요. 완료 후 `orchestrator.report_verification`으로 결과를 남겨요. |
| #43 수정 | 실패한 `VerificationResult`, 현재 `Ir` | 고친 `Ir` + 수정 이유 | 검증 → 수정 → 재검증 반복(최대 횟수 안)과 오류 사례 저장 테이블을 만들어요. 인터록 오류 고치기 테스트부터 써요. |
| #44 파일·영상 | `Ir` | GX Works 파일, 영상 | **먼저 GX Works가 설치된 Windows PC에서 가능성부터 확인**해요(`docs/poc-gxworks.md`에 기록). 가짜 파일을 성공으로 처리하지 않아요. |
| #45 통합·배포 | 위 전부 | 한 화면에서 전체 흐름 | #40~#43이 머지된 뒤 시작해요. 배포는 구조와 권한을 팀과 확인한 뒤 진행해요. |

- 이슈 #41~#43은 **에이전트 없이 파이썬 함수만으로 먼저 끝낼 수 있어요.** 에이전트는 그 함수를 호출하는 얇은 껍데기예요.
- #41 설계는 설계 에이전트(AI)가 회로(IR)를 만들고, 코드(`plc/design_check.py`)가 검사·IL 변환·저장해요. 자세한 내용은 [설계 단계](copilot-studio.md#설계-단계가-하는-일)를 보세요. 저장 성공도 `DESIGNING` 유지이고 안전 승인이 아니에요.
- 화면에서 결과를 보여 줄 부분(`frontend/src/RunStep.tsx`)은 통합할 때 같이 맞춰요.

## 5. Copilot Studio 에이전트를 만들 때

- 에이전트는 Copilot Studio에서 **담당자가 직접** 만들어요. 지침 예시와 MCP 도구 연결 방법은 `docs/copilot-studio.md`에 있어요.
- 에이전트 도구는 백엔드의 `/mcp`(MCP 서버)에 연결해요. 인증은 **공유 계정**으로 해요.
- 에이전트를 시험하려면 내 컴퓨터를 인터넷에 열어야 해요(개발 터널). 팀장에게 방법을 물어보세요.
- 같은 조직 계정이면 에이전트를 **편집자로 공유**해서 함께 고칠 수 있어요. 수정한 뒤에는 **게시**해야 적용돼요.

## 6. 자주 막히는 곳

| 증상 | 해결 |
|---|---|
| 홈페이지가 비어 있어요 | 프론트 서버를 껐다 켜고 새로고침(F5)해요. |
| `start-demo.bat`이 설치에서 멈춰요 | Python 3.12와 Node.js가 설치되어 있는지 확인해요. |
| 테스트가 실패해요 | 내가 바꾼 부분부터 확인하고, 계약을 바꿨다면 팀에 알려요. |
| 분석이 계속 "진행 중"이에요 | 데모 모드인지, 에이전트 연결 모드인지 확인해요. 연결 모드는 키와 터널이 필요해요. |
